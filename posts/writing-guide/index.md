실험 기록은 `posts/` 안의 마크다운 파일입니다. **글 하나 = 폴더 하나**이고, 그 글이 쓰는 이미지고 데모 HTML이고 전부 같은 폴더에 들어갑니다. 이 글도 `posts/writing-guide/` 안에 있고, 아래에 보이는 시계는 본문 안에서 돌아가는 데모입니다.

## 게시 절차

1. `posts/<slug>/` 폴더를 만듭니다. `<slug>`가 곧 주소(`#/blog/<slug>`)가 됩니다.
2. 폴더 안에 `index.md`를 넣고, 맨 앞에 frontmatter를 적습니다.
3. 본문에서 쓸 이미지·데모 HTML을 같은 폴더에 넣습니다.
4. 사이트 폴더에서 `node tools/build-posts.mjs`를 실행합니다. 게시 목록(`posts/index.json`)과 `file://` 미리보기 사본(`posts/posts.js`)이 다시 쓰이고, 미리보기를 새로고침하면 바로 보입니다.

```text
posts/
  writing-guide/
    index.md          ← 이 글
    demo-clock.html   ← 아래에서 실행되는 시계
```

`posts/<slug>.md`처럼 본문만 두는 평면 형식도 여전히 동작합니다. 이미지가 없는 짧은 기록이면 충분합니다.

## frontmatter 키

```md
---
title: 포스트 제목
date: 2026-11-11
tags: [llm, gpu, benchmark]
summary: 목록 카드에 한 줄로 표시될 요약.
demo: bench.html
demo_height: 420
draft: false
---
```

| 키      | 필수 | 설명                                                                        |
| ------- | ---- | --------------------------------------------------------------------------- |
| `title` | 권장 | 목록 카드·포스트 헤더·스크롤 시 고정되는 제목에 쓰입니다. 없으면 본문 첫 `#` 제목, 그것도 없으면 slug를 씁니다. |
| `date`  | 권장 | `YYYY-MM-DD`. Newest / Oldest 정렬은 이 값을 기준으로 정렬합니다.                |
| `tags`  | -    | `[llm, gpu]` 형태. 카테고리로 등록한 태그만 필터로 동작합니다.                |
| `summary` | 권장 | 목록 카드에 들어가는 한 줄 요약.                                            |
| `demo`  | -    | 이 포스트 폴더 안의 `.html` 파일 이름. 본문 안에 격리된 iframe으로 실행됩니다. |
| `demo_height` | - | 데모 프레임 높이(px). 기본 460.                                             |
| `demo_title` | - | 데모 프레임의 접근성 이름(aria-label). 기본은 포스트 제목.                                |
| `draft` | -    | `true`로 두면 게시 목록에서 빠집니다. 파일은 그대로 두고 안 보이는 상태로 보관합니다. |

## 실행되는 데모 끼우기

frontmatter에 `demo: bench.html` 한 줄이면 그 HTML이 포스트 본문 안에서 돌아갑니다. 어디에 놓을지 직접 정하고 싶을 때는 본문의 원하는 자리에 `[[demo]]`를 **한 줄 단독으로** 적어 주세요. 이 글은 그 방식으로 설명 뒤에 시계가 나옵니다.

[[demo]]

iframe은 `sandbox`로 격리됩니다. 실험 코드가 사이트 본문을 망가뜨리지 못하게 막는 장치이자, 데모를 쓸 때 알아야 할 제약입니다.

| 데모 안에서                                    | 동작 |
| ---------------------------------------------- | ---- |
| 캔버스·WebGL·Web Audio·`requestAnimationFrame`·버튼·폼 | ✓    |
| `alert`·`confirm`·팝업·포인터 록                | ✓    |
| 바깥 페이지 DOM 조작, `window.parent` 접근      | ✕ 차단 |
| `localStorage`·`sessionStorage`·쿠키·IndexedDB   | ✕ 차단 |
| 사이트 라우트로 이동(`#/blog/…`)                | ✕ 데모 안 링크는 `target="_blank"`로 |
| 같은 폴더의 다른 `.html`을 데모 안에 iframe으로 중첩 | ✓ (아래 미리보기 두 가지 참고) |
| CDN에서 ES 모듈·importmap으로 three.js 불러오기 | ✓ |
| 사이트의 로컬 JS·JSON을 런타임 `import`·`fetch`로 가져오기 | ✕ 차단 — 데모는 단일 파일로 |

위에서 보이는 시계 옆 문장이 그 상태를 직접 알려 줍니다 — 격리된 창에서는 저장소가 차단됩니다. 상태 유지가 필요한 데모는 프레임 아래 **새 창에서 열기**로 열었을 때 정상 동작합니다. 같은 파일을 별개로 게시하고 싶으면 그 링크만 공유하면 됩니다.

여러 실험을 한 화면에 비교해야 하면 데모 안에 iframe으로 다른 HTML을 넣으면 됩니다. 다만 미리보기 두 가지 모드에서 격리 강도가 다릅니다.

- **서버(`http://`) 미리보기·배포:** 데모는 항상 완전히 격리된 창으로 열립니다. 저장소· parent 접근이 막히고, 같은 폴더의 `.html` 중첩은 잘 불러옵니다.
- **`file://` 미리보기:** 브라우저가 격리된 창에서 로컬 파일을 불러오는 것 자체를 막기 때문에(`Not allowed to load local resource`) 데모 프레임을 같은 출처로 열어 줍니다. 이 경우만 저장소가 열리고, 프레임 아래 라벨이 `실행 중 · 로컬 미리보기(같은 출처)`로 바뀌어 구분됩니다.

배포된 사이트에서는 항상 격리되니, 저장소에 상태를 남기는 데모는 새 창에서 열었을 때만 동작한다고 생각하면 안전합니다.

### 데모 HTML 작성 규칙

- **단일 파일**로 만듭니다. CSS·JS를 안에 넣고, 이미지가 필요하면 같은 폴더에 두고 상대 경로로 참조하면 됩니다.
- `<meta name="viewport" content="width=device-width, initial-scale=1">`를 넣습니다. 모바일 프레임 안에서도 레이아웃이 지켜집니다.
- `<meta name="color-scheme" content="light dark">`나 `prefers-color-scheme`으로 다크 모드에 대응하세요. 사이트가 다크로 넘어가면 프레임 배경도 함께 바뀝니다.
- CDN 의존은 줄이세요. 오프라인 미리보기나 사내 방화벽에서 조용히 멈추는 대표적인 원인입니다.
- 높이가 모자라면 `demo_height`로 조절합니다. 모바일에서는 자동으로 화면의 68%를 넘지 않도록 줄어듭니다.
- 데모는 `index.md`와 같은 폴더에 있어야 합니다. 루트 기준 경로(`/demos/…`)는 게시 목록 검사 대상이 아니므로, 포스트 폴더에 두는 쪽이 안전합니다.

`demo` 값이 이 폴더에 있는 `.html`이 아니거나 사이트 밖을 가리키면 iframe 대신 `데모를 열 수 없습니다.` 안내만 표시됩니다.

## 이미지는 포스트 폴더에

| Markdown에서 쓴 경로 | 실제로 불러오는 파일 |
| -------------------- | -------------------- |
| `![설명](photo.png)` | `posts/<slug>/photo.png` |
| `![설명](../shared.png)` | `posts/shared.png` |
| `![설명](/assets/…)` | 사이트 루트 기준 (서버·`file://` 모두 동작) |
| `![설명](https://…)` | 그대로 외부에서 |

이미지는 폭만 맞춰(`max-width: 100%`) 둥근 모서리로 놓이고 나중에 로드됩니다. 캡션은 그리지 않으므로 `alt`는 대체 텍스트로만 쓰입니다.

## 마크다운 지원 범위

제목(`#`~`######`), 구분선(`---`), 인용(`>`), 순서·비순서 목록, 표(`:---:` 정렬, 칸 안에서 `<br>`), 강조·기울임·취소선, 인라인 코드와 언어 라벨이 붙는 펜스, 링크·이미지. HTML 태그는 문자로 취급되므로 본문에 직접 `<br>` 한 개만 쓸 수 있습니다. `<script>`나 `onerror=` 같은 것은 무력화되고, `javascript:` 경로도 차단됩니다.

## 태그 필터

포스트 태그를 Blog 목록의 필터 단추로 만들고 싶으면 `blog.js` 상단의 `CATEGORIES = []`에 태그 이름을 적습니다. 등록한 태그는 포스트 헤더에서도 클릭 가능한 링크로 바뀝니다.

## 미리보기와 배포

- 서버로 여는 방법(권장): 사이트 폴더에서 `python -m http.server` 후 `http://localhost:8000`. Markdown을 직접 읽으므로 새로고침만으로 반영됩니다.
- `index.html`을 더블클릭해서 여는 방법(`file://`): `fetch`가 차단되므로 `posts/posts.js` 사본을 사용합니다. 글이나 이미지를 고칠 때마다 `node tools/build-posts.mjs`를 다시 돌려야 반영됩니다.
- Vercel에는 `posts/` 폴더째 올라갑니다. 별도 설정은 없습니다.

## 자주 겪는 문제

| 증상 | 원인 | 처리 |
| ---- | ---- | ---- |
| 글이 목록에 안 보임 | `index.md` 이름이 틀렸거나 폴더 최상위가 아님 | `posts/<slug>/index.md` 구조 확인 후 빌드 재실행 |
| `file://`에서 내용이 옛날 것 | 사본 재생성을 잊음 | `node tools/build-posts.mjs` |
| 이미지가 깨짐 | 이미지를 다른 폴더에 둠 | 포스트 폴더로 옮기거나 `../` 경로로 참조 |
| 데모 자리에 안내 문구만 보임 | `demo` 값이 같은 폴더의 `.html`이 아님 | 파일 이름·위치 확인 |
| 데모에서 점수가 초기화됨 | 저장소 차단(의도된 동작) | 메모리 변수 사용, 또는 새 창에서 열기 |
| `[[demo]]`가 글자로 보임 | 다른 텍스트와 한 줄에 함께 있음 | `[[demo]]`만 단독으로 한 줄에 |
| 데모 프레임은 보이는데 안이 검은/하얀 화면 | 데모가 중첩한 로컬 HTML이 `file://`에서 차단됨 | 지금은 같은 출처로 열어 해결 — 그래도 안 되면 `python -m http.server`로 확인 |
| 데모가 three.js 등 CDN 모듈을 못 불러옴 | 오프라인·방화벽 | 인터넷 연결 확인, 또는 데모에 번들로 포함 |
